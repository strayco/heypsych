# Medication JSON v2 Specification - Content-Only Format

**Version:** 2.0
**Date:** December 2, 2025
**Canonical Reference:** [data/treatments/medications/alprazolam-Xanax-v2.json](data/treatments/medications/alprazolam-Xanax-v2.json)
**Target:** All medication JSON files (500+ files)

---

## Executive Summary

Migrate all medication JSON files from the legacy format (with UI/design/SEO blobs) to the v2 content-only format. The v2 format contains **ONLY domain content** - no visual design, no SEO extensions, no UI hints. All presentation logic is handled centrally by the system.

**Goal:** Reduce file size by 60%, eliminate data duplication, enable central SEO/schema management, and require zero per-entity engineering.

## Architecture Overview

### Current (Legacy) Flow
```
JSON (1,070 lines)
├── Domain content
├── visual_design (55 lines) ❌
├── seo_extensions (357 lines) ❌
├── ui_hints in every section (42+ lines) ❌
└── Inline schema_org
```

### New (v2) Flow
```
JSON (577 lines) ✅
├── Domain content ONLY
└── Minimal SEO overrides (optional)

↓

Central Engines Handle:
├── SEO Engine → Auto-generate metadata
├── Schema Engine → Auto-generate JSON-LD
└── Section Registry → Provide UI hints
```

**Result:** 60% smaller files, 100% automated SEO/schema, zero maintenance overhead.

## What to Remove

### ❌ 1. Remove `visual_design` Object

**Entire object must be deleted.** Contains fonts, colors, spacing, animations, cards, icons, etc.

```json
// ❌ DELETE THIS ENTIRE BLOCK
"visual_design": {
  "fonts": { ... },
  "colors": { ... },
  "spacing": { ... },
  "animations": { ... },
  "cards": { ... },
  "icons": { ... }
}
```

**Why:** All visual design is centralized in the design system. Individual JSONs should not specify how they look.

---

### ❌ 2. Remove `seo_extensions` Object

**Entire object must be deleted.** Contains keywords, search intent, and inline schema_org.

```json
// ❌ DELETE THIS ENTIRE BLOCK
"seo_extensions": {
  "keywords": [ ... ],
  "search_intent": { ... },
  "search_intent_phrases": [ ... ],
  "search_intent_clusters": [ ... ],
  "schema_org": { ... }  // 200+ lines of inline schema
}
```

**Why:** SEO and schema.org are auto-generated by central engines. No inline overrides allowed.

---

### ❌ 3. Remove UI Hints from All Sections

**Remove these fields from EVERY section:**
- `ui_hints`
- `ux_display`
- `collapsible`
- `visual_priority`
- `card_style`
- `animation`
- `progressive_disclosure`

```json
// ❌ DELETE THESE FIELDS FROM EVERY SECTION
{
  "type": "patient_experience",
  "heading": "What People Feel",
  "ui_hints": { ... },           // ❌ DELETE
  "ux_display": "...",            // ❌ DELETE
  "collapsible": false,           // ❌ DELETE
  "items": [ ... ]                // ✅ KEEP
}
```

**Why:** Presentation logic is centralized in the section registry. Sections should only specify content (type, heading, items), not how they're rendered.

### ✅ 8. Minimal SEO Overrides (Optional)

**Only these fields are allowed in the `seo` object:**

```json
{
  "seo": {
    "title": "Optional custom title (overrides auto-generated)",
    "description": "Optional custom description (overrides auto-generated)",
    "canonical": "Optional custom canonical URL",
    "no_index": false
  }
}
```

**Default (if `seo` not provided):**
- Title: Auto-generated from `name + brand_names + "Uses, Side Effects, Dosage | HeyPsych"`
- Description: Auto-generated from `name + primary_indications + drug_classes`
- Canonical: Auto-generated from `slug`

**No other SEO fields allowed.** No keywords, no search_intent, no schema_org.

## Validation Steps

### Step 1: Run Content Schema Validator

```bash
# Validate single file
npx tsx scripts/validate-content-schema.ts

# Validate with verbose output
npx tsx scripts/validate-content-schema.ts --verbose

# Validate specific file
npx tsx -e "
import { validateFile } from './scripts/validate-content-schema.ts';
const result = validateFile('./data/treatments/medications/your-drug.json');

"

```
✅ Valid: true
✅ Errors: []
⚠️ Warnings: [] (or minor warnings)

## Acceptance Criteria

A migrated medication JSON is considered **complete and valid** when:

1. ✅ **Validation passes:** `npx tsx scripts/validate-content-schema.ts` returns valid=true
2. ✅ **No forbidden fields:** No visual_design, seo_extensions, ui_hints anywhere in file
3. ✅ **All required fields present:** kind, slug, type, name, summary, description, sections
4. ✅ **File size reduced:** At least 40% smaller than legacy file
5. ✅ **TypeScript compiles:** `npx tsc --noEmit` succeeds
6. ✅ **Page renders correctly:** All visual components work (carousel, stat card, etc.)
7. ✅ **SEO auto-generated:** Title, description, canonical correct
8. ✅ **Schema auto-generated:** All 5+ schemas present and valid
9. ✅ **Content parity:** All clinical information preserved
10. ✅ **CI passes:** GitHub Actions workflow succeeds

## Migration Script

### Automated Migration (Recommended)

```bash
#!/bin/bash
# migrate-medication.sh
# Usage: ./migrate-medication.sh alprazolam-Xanax

SLUG=$1
LEGACY_FILE="data/treatments/medications/${SLUG}.json"
V2_FILE="data/treatments/medications/${SLUG}-v2.json"

echo "🔄 Migrating ${SLUG} to v2 format..."

# 1. Read legacy JSON
if [ ! -f "$LEGACY_FILE" ]; then
  echo "❌ Legacy file not found: $LEGACY_FILE"
  exit 1
fi

# 2. Strip forbidden fields using jq
jq 'del(.visual_design) | del(.seo_extensions) |
    .sections |= map(del(.ui_hints) | del(.ux_display) | del(.collapsible))' \
  "$LEGACY_FILE" > "$V2_FILE"

echo "✅ Created v2 file: $V2_FILE"

# 3. Validate v2 file
npx tsx -e "
import { validateFile } from './scripts/validate-content-schema.ts';
const result = validateFile('$V2_FILE');
console.log('Valid:', result.valid);
console.log('Errors:', result.errors);
if (!result.valid) process.exit(1);
"

if [ $? -eq 0 ]; then
  echo "✅ Validation passed"

  # 4. Rename legacy file
  mv "$LEGACY_FILE" "${LEGACY_FILE}.backup"
  echo "✅ Backed up legacy file: ${LEGACY_FILE}.backup"

  # 5. Rename v2 file to production name
  mv "$V2_FILE" "$LEGACY_FILE"
  echo "✅ v2 file now active: $LEGACY_FILE"
else
  echo "❌ Validation failed. Check errors above."
  rm "$V2_FILE"
  exit 1
fi
```

## Common Issues & Solutions

### Issue 1: Validation fails with "Missing required field: heading"

**Cause:** Some sections don't have `heading` field

**Solution:** Add `heading` field to all sections
```json
{
  "type": "indications",
  "heading": "What It's Used For",  // ← Add this
  "items": [...]
}
```

---

### Issue 2: Page renders but visuals missing

**Cause:** Section registry not providing ui_hints for that section type

**Solution:** Check that section type is registered in [src/lib/content/section-registry.ts](src/lib/content/section-registry.ts). If not, add it.

---

### Issue 3: Dosing information not displaying

**Cause:** Renderer expects specific field structure that doesn't match your JSON

**Solution:** The renderer now handles any fields in `adult` object dynamically. Just ensure `adult` is an object with key-value pairs.

```json
{
  "type": "dosing",
  "heading": "Dosing Information",
  "adult": {
    "any_field_name": "Any value",
    "another_field": "Another value"
  }
}
```

---

### Issue 4: SEO title/description not what I expect

**Cause:** Auto-generation doesn't match your preference

**Solution:** Add explicit `seo` overrides
```json
{
  "seo": {
    "title": "Your custom title",
    "description": "Your custom description"
  }
}
```
